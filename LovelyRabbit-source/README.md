# 兔兔要减肥 lovely rabbit

当前采用「冷感芭蕾」主题：浅冷米色背景、浅灰粉主卡片、浅蓝/浅粉/浅紫任务卡，以及蝴蝶结、蕾丝边和绑带装饰，所有色块使用纯色。设置页不再提供深色模式开关。首页主卡片按草图展示心愿积分、饮食入口、体重三层，底行按钮记录体重。奖励卡图案统一为礼物。心愿商店使用正方形卡片和可左右滑动的单条横向心愿轴，节点仅显示心愿序号和积分门槛，数量增加时不换行。成长轨迹保留任务、积分、完成率与体重趋势。导出结构中的 lifetimeXP/availableXP 等字段名保持兼容。

面向个人使用的移动端 PWA：用习惯打卡、积分与心愿清单，收藏日常的成长。React + TypeScript + Vite + Tailwind CSS + Dexie IndexedDB + Lucide + vite-plugin-pwa，无账号、无后端、无付费 API、无外部字体/CDN 依赖。

点击首页昵称可直接改名；日历标题右侧的「成长轨迹」进入任务统计、四周活动和体重趋势。主导航为四项，日记按日期显示在打卡下方。已完成任务仅显示「+数字」，日历只展示已完成任务。装饰为本地 SVG，中文衬线标题使用设备字体回退，不加载外部字体或图片。

## 饮食记录

早餐、午餐、晚餐、加餐入口打开居中对话框，可搜索本地 1643 条食物、按标签添加个人食物，用滚轮或直接输入数量，支持 g 和个人标定的常用单位。日历在打卡和日记之间显示饮食记录，支持修改、删除与补记。首次可填写性别参数、年龄、身高、体重、活动情况，以 Mifflin–St Jeor 近似式估算基础代谢；当前差值按基础代谢减已记录摄入，明确不等同全天实际缺口，不计活动或运动，不改变积分。详见 [NUTRITION.md](NUTRITION.md)。运动记录已接入 2024 官方成人表，详见 [EXERCISE-DATA-SOURCES.md](EXERCISE-DATA-SOURCES.md)。

## 本地运行

需要 Node.js 22.18+，推荐 Node.js 24 LTS。Windows PowerShell 如果阻止运行 npm.ps1，请使用 `npm.cmd`。

```powershell
npm install
npm run dev
```

在电脑打开 http://localhost:5173 。开发服务器只用于开发，不提供生产离线缓存。

```powershell
npm run build
npm run preview
```

生产预览地址 http://localhost:4173 。Service Worker 在生产构建中生成；第一次联网打开后再测试离线。两个端口是不同来源，数据彼此独立。不要直接双击 dist/index.html。

## 日常使用

1. 第一次打开会出现心愿清单，默认 6 个阶段，可改为 1–9 个；也可关闭弹窗直接使用默认配置。
2. 默认每日任务共四项：热量缺口300kcal、喝水1500ml、走路10000步、12点前睡觉。可修改名称和执行日；不再提供训练次数选项。旧版未自定义的五项默认配置会自动迁移，已经完成的任务和历史记录保留原快照。
3. 每项任务每天仅有一次有效记录。随机 XP 在首次完成时抽取 2–6，未完成时隐藏，完成后在页面中央显示实际加分；撤销后再完成沿用原值（已有旧版快照保留其原始积分）。所有任务仅支持随机 2–6 积分，旧版已获得的固定积分保留。最多安排 8 项/天。
4. 点击任务完成，再次点击可撤销。已兑换的积分不能造成负余额，因此余额不足以回滚时会阻止撤销，并提示原因。
5. `lifetimeXP` 是所有有效打卡 XP 的总和，`availableXP = lifetimeXP − 历史兑换消费`。它们从记录计算，避免余额漂移。兑换不降低累计经验与阶段；撤销会回滚真实累计经验。
6. 阶段由心愿的「作为成长阶段」开关定义，并按价格升序排列。累计 XP 达到门槛即进入下一阶段，不必先兑换；之前的心愿仍可兑换。至少保留一个阶段，阶段价格不能重复。通过添加、删除、切换阶段心愿，可以调整阶段数量。
7. 默认六档为 66、128、188、218、288、388 XP。首次心愿清单可扩展到 468、568、648 XP；648 档默认示例是「给喜欢的游戏充一个648」。任何奖励都可编辑，不涉及实际支付或自动购物。奖励可以多次兑换，每次确认并留存历史。
8. 日历仅展示选中日期已经完成的打卡和当天日记，未打卡任务不显示。当天打卡可在首页操作；选择今天或之前三天可点击“补录打卡”录入遗漏任务，最近三天的完成记录仍可撤销，更早记录只读，没有惩罚性连续打卡。
9. 首页顶部显示下一阶段的心愿、所需 XP、按累计获得积分计算的剩余 XP 和进度，不显示 LV 或等级称号。底部导航仅保留首页、日历、奖励、设置。
10. 首页「写今天的日记」打开一个自由输入框。日历选择日期后，在当天打卡记录下方查看、补写或编辑日记。日记不限制为最近 3 天，不允许提前写未来日期，不参与积分；每个日期保存一篇。旧版四项记录保留，并以完整连续文字显示，编辑时也只提供一个框。

## 本地数据与备份

- 数据存在当前浏览器、当前网站来源的 IndexedDB `beauty-quest` 数据库中，表为 `states`，主键为 `main`。关闭网页、重启浏览器或设备不会主动删除它；浏览器清理、无痕模式退出、系统存储回收可能删除数据。
- 「设置 → 请求浏览器持久存储保护」可申请持久存储，是否授予由浏览器决定。它不等于永久备份。
- 「导出 JSON 备份」发起文件下载。请检查下载列表确认文件已保存；浏览器下载被限制时，可选择「查看与复制完整备份」，保存完整文本到自己的安全位置。
- 导入文件或粘贴完整 JSON 都会先校验版本、字段、日期、重复记录、任务引用和非负余额，再次确认后完整替换。无效文件不会更改原数据。最多 15 MB；兼容旧备份中的封面数据，当前奖励图案统一显示礼物。
- 换手机：旧手机导出 → 把文件传到新手机 → 打开相同应用 → 设置 → 导入确认。没有自动云同步，也不会上传你的备份。
- 切换浏览器、域名、协议或端口会进入另一份独立存储。正式长期使用建议固定 HTTPS 域名。
- 清空操作需要两次确认，第二次必须输入「清空」。

## 工程结构

```text
src/
  App.tsx               四个页面与事务交互
  components/           可访问弹窗、任务卡、表单、备份工具
  constants.ts          图标和主观问题
  model.ts              v2 数据结构、v1 迁移、校验、积分和阶段规则
  db.ts                 Dexie 数据库、串行事务、原子恢复
  model.test.ts         领域逻辑及 IndexedDB 测试
  style.css             移动端样式、深色模式、安全区、减少动画
public/                 192/512 图标、maskable 图标、Cloudflare 缓存头
vite.config.ts          Manifest 与 Workbox 离线预缓存
playwright.config.ts    Chromium 手机尺寸验收
vitest.config.ts        单元测试范围
```

记录使用本地日历日期（而非 UTC 截断），快照保留当时名称、积分、训练标识。每次应用启动补齐使用开始至今的间隔日期；已保存日期不会被后续任务编辑改写。多个页面通过 Dexie liveQuery 同步；打卡和兑换读取最新数据并在 IndexedDB 事务内提交。

数据和数据库分别有版本号：JSON `version: 2`，Dexie schema version 1（表结构未变）。支持显式迁移 v1 本地数据和备份，新增营养字段初始化为空；严格校验 v2，拒绝未知版本与损坏记录，不清空旧数据。

## 产品取舍

需求中「热量缺口 ≥300kcal」与「不设计限制热量等积分任务」冲突，因此采用后者，改为「好好吃饭，均衡一餐」。目标体重保留为个人可选关注值，默认 100 斤（50 kg），不参与评分、阶段或倒计时。

这是手动记录工具：不会读取计步器、自动识别喝水或训练；不接入健康账号，不追踪卡路里，不验证身体变化。云端部署与手机实机验收需要人工完成，当前交付不代表已经发布到公网。

## 双击启动已构建的版本（Windows）

当前项目已经含有 dist。双击项目根目录或 outputs 文件夹中的 `start-local.cmd`，然后访问 http://localhost:5173/ 。保持启动窗口打开，按 Ctrl+C 可停止。若从源码 ZIP 新解压，请先执行 npm install 和 npm run build。

该入口用 Node.js 直接提供 dist 中的生产版文件，不经过 Vite 配置编译；适用于后台启动 Vite 时遇到配置读取权限问题的情况。服务仅绑定本机 127.0.0.1，不对局域网开放。关闭窗口、重启电脑或工具会话被回收后，需要重新启动；localhost 不是永久托管地址。

任务完成反馈：未完成时隐藏具体 XP，首次完成随机任务后抽取 2–6 XP，中央浮层仅显示「任务完成」和加分。撤销时显示回滚数字，重新打卡保留已抽取结果。旧版快照保留原积分。新版 npm 命令使用 Node 原生配置加载，避免后台环境的配置编译权限错误；推荐 Node 24。

## 2024 官方运动记录

首页「运动」及日历「记录运动」已接入官方 2024 成人表：22 类、1,111 个条目，支持搜索、时长滚轮、体重核对、消耗估算、编辑删除、离线及 JSON 恢复。适用 19–59 岁，不自动加减积分或叠加首页热量差额。详见 [运动数据与计算说明](EXERCISE-DATA-SOURCES.md)。


## 个人食物与运动目录

自定义食物在添加时立即保存，不要求同时完成饮食记录。个人运动可填写名称、参考分钟和千卡保存，之后按时长比例复用；来源标为用户填写，不混入官方 MET。个人目录与公共离线目录一起搜索，使用 IndexedDB 持久化，并纳入 JSON 导出恢复。不同浏览器/设备的新增内容各自独立，没有云同步。旧 v2 备份缺少个人运动目录时补空数组，JSON版本不变。饮食使用居中对话框。


## 已确认食物均值补充库

现有1643条食物之外，接入用户确认的179条每100g均值记录（public/data/reviewed-foods.json），同名搜索优先显示补充均值。scripts/data/reviewed-100g.json保存批准快照，scripts/import-reviewed-foods.py可重建公共补充库及来源摘要。没有每100g数据的623条不接入。PWA离线缓存包含补充库。

无糖豆浆额外提供80千卡/杯，与30千卡/100g独立使用，未假设一杯有多少克。JSON v2的饮食记录可选unitCalories保存当时每单位热量；此时gramsPerUnit为null。旧按克和个人标定记录继续使用原有结构与校验。导入时会校验两种模式互斥及计算一致性。历史记录不随公共目录更改而重算。补充值为用户提供素材的整理均值，原始目录和个人数据均保留。
